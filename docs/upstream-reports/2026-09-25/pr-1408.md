# TradingAgents PR #1408: market data resilience, tool error shielding, `doctor` command

- Author: SinghAbhinav04 · opened 2026-09-24 · head `888c6c10ca81` · +294/-2, 7 files
- State: open, not draft, mergeable. No reviews, no comments, no CI checks reported.

## Summary

**Verdict: adapt (small).** Of the five bundled changes, one idea is worth taking. When the verified snapshot fails, the tool should return a typed sentinel with an explicit "do not fabricate" instruction, not a bare error. Berkshire already returns a readable error string (REQ-DATA-06), but that string has no sentinel and no instruction. The `doctor` command, the yfinance fallback and the LangGraph `ToolNode` shielding do not transfer to Berkshire.

## What it does

The PR bundles five unrelated changes:

1. **Snapshot sentinels** (`tradingagents/agents/tools.py:93-126` at head). `get_verified_market_snapshot` is the only analyst tool that bypasses `route_to_vendor`. It calls `build_verified_market_snapshot` → `load_ohlcv` directly, so an invalid or delisted ticker raises `NoMarketDataError` or `ValueError` (`snapshot.py:39,46` on main) through the graph and aborts the run. The PR catches `NoMarketDataError`, `VendorRateLimitError`, `ValueError` and then any `Exception`. It returns `NO_DATA_AVAILABLE:` / `DATA_UNAVAILABLE:` strings that copy the router's wording (`router.py:262-280` on main).
2. **`ToolNode(..., handle_tool_errors=True)`** for every analyst tool node (`tradingagents/graph/setup.py:102`). Any tool exception becomes an error `ToolMessage` and no longer aborts the graph.
3. **OHLCV fallback** (`tradingagents/dataflows/vendors/yahoo/ohlcv.py:252-259`). When `yf.download` returns an empty frame, the PR retries once with `yf.Ticker(canonical).history(...)` before `raise_for_empty`.
4. **CLI** (`cli/main.py:79-86`). `analyze` catches `KeyboardInterrupt` (exit 0) and any `Exception` (prints one line, exit 1, and a `--checkpoint` resume hint).
5. **`tradingagents doctor`** (`cli/doctor.py`). It prints the Python version, checks that the cache directory is writable, shows five LLM API-key env vars (masked) and HEAD-probes five vendor hosts with `vendor_reachable`.

## Soundness

- **(1) fixes a real bug.** On main, an unknown symbol crashes the graph at the snapshot tool, while every routed tool degrades to a sentinel. The `NoMarketDataError` and `VendorRateLimitError` branches (`tools.py:96-114`) are correct and consistent with the router. The date is clamped with `as_of` before the `try`, so point-in-time safety is unchanged.
- **The catch-alls reverse a deliberate upstream policy.** `router.py:99-102` says core categories (prices, fundamentals, news) "still raise so a broken primary is loud", and `router.py:290` re-raises `first_error`. The PR undoes this in two places:
  - `tools.py:121` turns *any* exception in the snapshot into "Proceed without it". This includes programming errors in the indicator code.
  - `setup.py:102` turns every uncaught tool exception, including core price, fundamentals and news failures, into an error `ToolMessage` that the LLM reads and writes around.

  The run now finishes quietly on broken data, which is the failure mode the snapshot was built to prevent (#830). This is a design regression, not a crash fix.
- **`tools.py:115` labels every `ValueError` as `NO_DATA_AVAILABLE`.** That includes `VendorNotConfiguredError`, which subclasses `ValueError` (`errors.py`), and any `ValueError` from the indicator math. A code defect then reads to the agent as "this symbol has no data".
- **The fallback (`ohlcv.py:255`) bypasses `yf_retry`.** A `YFRateLimitError` there is swallowed at debug level. `raise_for_empty` still asks `vendor_reachable` whether Yahoo is up, so the typed error stays correct. The `history()` frame is tz-aware and carries `Dividends`/`Stock Splits` columns, but `_clean_dataframe`/`_normalize_dates` handle the tz, so this looks harmless. The patch adds one extra network call for every truly invalid symbol. There is no evidence that `download` returns empty while `history` succeeds. The claim is untested.
- **CLI (`main.py:79-86`) has three problems:**
  - Ctrl-C exits with code 0, so a script sees an interrupted run as a success (the convention is 130).
  - The blanket `except Exception` drops the traceback. That hurts bug reports.
  - The resume hint only prints when `--checkpoint` was passed explicitly. It stays silent when checkpointing is enabled through `TRADINGAGENTS_CHECKPOINT_ENABLED` (`checkpoint is None`).
- **`doctor` (`doctor.py:131`) always prints "System ready for running analyses".** It does so with zero keys configured or with every vendor unreachable, and it always exits 0, so it cannot gate anything. The LLM-key list is a hard-coded subset of the supported providers. `test_run_doctor_executes_without_error` (`tests/test_cli_doctor.py:29`) creates and writes to the real configured cache directory.

## Value to Berkshire

Berkshire counterparts:

- **Snapshot failure.** `berkshire/data.py:131-137` raises `ValueError` when there are no rows. `cmd_data` catches everything (`berkshire/cli.py:145`) and prints `Data tool snapshot failed for [...]: ValueError: ...`. This is REQ-DATA-06, tested by `tests/test_data.py:84`. Berkshire never crashes here, and the Claude subagent always gets a readable string. Berkshire is already better than upstream main on robustness.
- **What Berkshire lacks** is the *honesty directive*:
  - The failure string has no stable sentinel. It does not separate "no data for this symbol" from "vendor unreachable", and it does not tell the agent not to estimate.
  - `agents/market-analyst.md:36` tells the analyst to treat the snapshot as the source of truth, but says nothing about what to do when it fails.

  In a scheduled tick (REQ-SCHED-05), a snapshot failure could therefore end in a market report with numbers from memory. Adding the directive is a small grounding improvement.
- **OHLCV fallback.** Not applicable. Berkshire already fetches with `yf.Ticker(...).history` (`berkshire/data.py:70`), and `check_listed` screens unknown tickers at run start.
- **`handle_tool_errors`.** Not applicable. There is no LangGraph, and tools are CLI calls whose failures are already strings.
- **`doctor`.** Berkshire runs Claude-only inside Claude Code, so there are no LLM keys to check. A health check of yfinance and eToro reachability could be useful someday, but it is CLI chrome and not asked for.
- **CLI Ctrl-C handling.** Not applicable. `/berkshire:analyze` persists every step (the run directory is the checkpoint).

## Proposed Berkshire change

Adopt only the sentinel-plus-directive idea:

1. `berkshire/cli.py:145` (`cmd_data`): prefix failures with a sentinel.
   - `NO_DATA_AVAILABLE:` for the no-rows `ValueError` from `_history_for`, and for the empty result of `tool_stock` (`data.py:143-144`).
   - `DATA_UNAVAILABLE:` for everything else, such as network errors or exceptions from yfinance.
   - In both cases append "Report the data as unavailable; do not estimate or fabricate values." Keep the exception type and message so real bugs stay visible, and do not reword them as "no data".
2. `agents/market-analyst.md` (next to line 36), and the matching line in the fundamentals, news and sentiment analyst personas: if a tool returns `NO_DATA_AVAILABLE` or `DATA_UNAVAILABLE`, say so in the report and its table, and make no exact numeric claim for that data.
3. Amend **REQ-DATA-06**: "...a readable error string with a `NO_DATA_AVAILABLE`/`DATA_UNAVAILABLE` sentinel and a do-not-fabricate instruction, never a traceback". Extend TST-DATA-06 (`tests/test_data.py:84`) to cover both sentinels. The persona line is covered by an inspection check under REQ-ROLE-05 or REQ-DATA-06.

Decline items 2 to 5 for the reasons above.
