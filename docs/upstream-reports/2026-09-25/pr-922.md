# PR #922: feat(sentiment): add Bluesky, Mastodon & Fear & Greed sources (free, no-auth)

Head `0588a2e52f67` · author Vanszs · opened 2026-05-29, not updated since · 5 files, +414/−11 · mergeable: CONFLICTING

## Summary

**Verdict: adapt, Bluesky only.** Add Bluesky as a fourth sentiment source, windowed to the analysis
week with `since`/`until`. Drop Mastodon, which is thin and prone to hashtag collisions. Drop the
Fear & Greed feed: it is the *crypto* index, it is not point-in-time, and the PR presents it as a
general market-mood gauge.

## What it does

The PR adds three stateless fetchers:

- `dataflows/bluesky.py` calls the public AT Protocol `app.bsky.feed.searchPosts`, searching for `$TICKER`.
- `dataflows/mastodon.py` reads the public hashtag timeline `#TICKER` on `MASTODON_INSTANCE`
  (default mastodon.social).
- `dataflows/fear_greed.py` reads the Alternative.me index, current value plus 7 days, cached
  in-process for 1 h.

`sentiment_analyst.py` calls all three before the model runs and adds three `<start_of_*>` blocks to
the single-shot prompt, next to the existing news, StockTwits and Reddit blocks. Its source-breakdown
instruction now names six sources. The goal is broader retail coverage without API keys, following
the pre-fetch, no-tool-calling design from #557.

## Soundness

- **Look-ahead leak (main defect).** Every new fetcher returns the newest items with no date bound.
  - `bluesky.py:37` sends `sort=latest` without `since`/`until`, although the API supports both.
  - `mastodon.py:44` reads the live timeline and ignores `start_date`/`end_date`.
  - `fear_greed.py:27` always fetches today's index. The 1 h cache at `fear_greed.py:15-24` also
    serves that same value to every trade date in a backtest.

  Upstream fixed this class of leak for StockTwits and Reddit in #1220: main now passes
  `start_date`/`end_date` to both fetchers. This PR predates that fix and would reintroduce the leak
  on three new channels. That makes it unusable for backtests as written.
- **Wrong index.** Alternative.me's F&G is the *Crypto* Fear & Greed Index (the output header at
  `fear_greed.py:50` even says so). The prompt at `sentiment_analyst.py:+167` introduces it as a
  "macro risk-on/risk-off proxy" for any ticker. For equities it is noise that looks like signal.
  The hard-coded `Interpretation` text at `fear_greed.py:52-62` ("potential contrarian buy signal")
  also puts a directional opinion into what should be raw data.
- **Mastodon quality.** `mastodon.py:41` strips `$` and uses the bare ticker as a hashtag. Tickers
  such as `F`, `T`, `AI`, `ON` and `ALL` then collide with unrelated hashtags. `mastodon.py:63`
  removes HTML tags but never calls `html.unescape`, so `&amp;` and `&#39;` reach the prompt. A
  mastodon.social-only timeline is also a very small sample.
- **Inconsistencies.**
  - `fear_greed.py:10` uses `requests`, while the other two fetchers use `urllib`.
  - F&G failures return free text instead of an `<unavailable>` placeholder, so the prompt's
    placeholder convention breaks.
  - `int(current.get("value", 0))` at `fear_greed.py:39` sits inside a bare `except Exception`.
    That is safe, but it hides parse bugs.
- **Latency.** The six fetches run sequentially, each with up to a 10 s timeout, so the worst case
  adds about 30 s per run.
- **What is right.** Failures degrade to strings and never raise. Bluesky post text is truncated.
  The tests cover parsing, empty results and HTTP errors.

## Quality and maturity

- **Tests.** Adds `tests/test_sentiment_sources.py` (160 lines), covering fetcher parsing and
  degradation plus prompt wiring. The tests do not cover the F&G fetcher or any date windowing.
- **CI.** No CI runs are reported.
- **Review.** Only bot reviews: Copilot left 7 comments, and Gemini asked for concurrency, HTML
  unescape, a scheme check on the instance URL, and `urllib` instead of `requests`. No maintainer has
  responded, and the author has not updated the PR in about four months.
- **Merge state.** It conflicts with main. Upstream has since moved the fetchers to
  `dataflows/vendors/`, added `jev_screen` and date-windowed the social fetchers.
- **Outlook.** A merge in this form is very unlikely. The earlier attempt, #585 (Reddit + Fear &
  Greed), was closed. If any of this lands, expect a date-windowed Bluesky piece, not the whole PR.

## Value to Berkshire

- **Bluesky has modest value.** It is a real additional retail channel. It is also the only social
  API here with server-side date bounds (`since`/`until`), so, unlike StockTwits, it can give a
  genuinely point-in-time read for past dates. That fits Berkshire's honesty rules:
  - REQ-DATA-01: clamp dated data to the run's trade date.
  - REQ-DATA-07: label non-point-in-time sources as current.
  - `agents/sentiment-analyst.md:26`: drop posts after the analysis date and say when the read is
    not point-in-time.
- **Mastodon has little value.** It adds a small, noisy sample for extra prompt tokens.
- **Fear & Greed has negative value** for equities, as argued under Soundness. For crypto
  (REQ-FLOW-06) it would be relevant, but only as a current reading. The News Analyst's web search
  already covers market mood.
- **Where Berkshire already stands.** Berkshire has the no-invention guard ("Never invent posts",
  `agents/sentiment-analyst.md:14`) and a per-source `<unavailable>` rule. Its sentiment agent
  fetches through WebFetch at run time (UP-016), so a new source is a persona edit, not engine code.

## Proposed Berkshire change

Add Bluesky as source 4 in `agents/sentiment-analyst.md` (after line 12):

- Fetch with WebFetch from
  `https://public.api.bsky.app/xrpc/app.bsky.feed.searchPosts?q=%24<SYMBOL>&sort=latest&limit=50&since=<START>T00:00:00Z&until=<END>T23:59:59Z`.
- Use the run's 7-day window.
- Report the likes, reposts and replies on each post.
- Write `<unavailable>` on failure.

Also:

- Update the "three complementary sources" text (line 8) and the high-confidence rule (line 39)
  to count four sources, but still grant high confidence when Bluesky is empty. Bluesky coverage of
  small caps is sparse, and an empty result must not push confidence down.
- Amend REQ-ROLE-03 (Sentiment: "news plus web search of StockTwits, Reddit and Bluesky") and
  TST-ROLE-03 in `docs/test-plan.md:56`.
- Extend the persona inspection in `tests/test_plugin.py:48` so it asserts the Bluesky URL and the
  `since`/`until` window.

Do not add Mastodon or the Crypto Fear & Greed Index.

## Effort and risk

**S** (under 1 h): one persona edit, one requirement row, one test-plan row and one inspection
assertion. The risk is low. The source is additive, degrades to `<unavailable>`, and needs no engine
or dependency change. The main risk is that `searchPosts` is geo-blocked or rate-limited on some
networks. The PR's own docstring says so. The `<unavailable>` rule already handles it.
