## Summary

**Verdict: adapt.** Berkshire analyses ETFs as if they were companies. The user's watchlist holds GLD, SPY, AGG and EIMI.L, so this gap affects every scheduled tick. The PR's core idea is worth taking: detect the ETF, switch to fund-shaped prompts, give the analyst a profile and holdings tool with concentration metrics, and add ETF risk axes. Build it the Berkshire way, as an asset mode like crypto (REQ-FLOW-06) with one new data tool. Leave out the drill-down, the vendor-wrapping placeholders and the Alpha Vantage path.

## What it does

- **Detection.** `is_etf_ticker` reads yfinance `info.quoteType == "ETF"` through an LRU-cached `.info` fetch (`tradingagents/dataflows/etf_utils.py:44-62,80`). `leverage_descriptor` reads `info.category` (`"Trading--Leveraged/Inverse …"`) to flag daily-reset products.
- **Placeholders.** When `interface.py` loads, it wraps every vendor implementation of `get_fundamentals`, `get_balance_sheet`, `get_cashflow`, `get_income_statement` and `get_insider_transactions` (`interface.py:153-172`). For an ETF ticker these return "ETF, company-style X does not apply, use get_etf_profile/get_etf_holdings".
- **New tools.** `get_etf_profile` covers AUM, expense ratio, NAV, category, yield, returns, strategy text, asset-class and sector weights. `get_etf_holdings` returns the top N as CSV plus a concentration block: the largest holding, the top-N aggregate weight, and a Herfindahl index over the top N. Both have a yfinance implementation (`yfinance_etf.py`) and an Alpha Vantage `ETF_PROFILE` implementation (`alpha_vantage_etf.py`). A third tool, `get_etf_top_holdings_drilldown`, fetches fundamentals and news for each of the top N constituents, with truncation (`etf_drilldown.py`).
- **Prompts.** For an ETF, the Fundamentals Analyst gets an ETF-specific system message. `build_instrument_context` adds "this is a fund, not a company" and, for leveraged or inverse products, a structural warning about daily-reset decay (`agents/utils/agent_utils.py:82`). All three risk debaters get an appended `build_etf_risk_block` (`agent_utils.py:99`) covering liquidity/AUM, concentration, tracking/expense drag, structure (leveraged decay, synthetic/swap counterparty risk), premium/discount to NAV, and constituent catalysts.

The problem it solves: on an ETF, company-financial tools return empty or misleading data, such as a P/B for a gold trust. The analyst then invents "company margins" for an index basket, and the risk debate argues about a fund's balance sheet.

## Soundness

The mechanism is reasonable, but it has several real issues:

1. **Look-ahead and point-in-time honesty.** The profile and holdings are always today's (`yfinance_etf.py:57,167` stamp only `datetime.now()`), and nothing tells the agent they may not match the analysis date. The drill-down calls `get_fundamentals` for each constituent with `end_date` as the "look-ahead cutoff" (`etf_drilldown.py:78`), but `.info`-based fundamentals are current data whatever date is passed. In a backtest, today's top holdings and AUM leak into past decisions. Berkshire must label all of this as current (REQ-DATA-07).
2. **Cached failure means a silent misclassification.** `_yfinance_info` returns `{}` on any exception, and the `lru_cache` keeps that result (`etf_utils.py:44-62`). One transient yfinance error or rate limit makes the ticker "not an ETF" for the rest of the process. In a long-running process that runs many tickers, this silently reverts to company mode. Berkshire runs the profile once per run and persists it, so it limits the damage, but it should still fail open visibly.
3. **Detection costs network calls in odd places.** `is_etf_ticker` runs inside every protected vendor call, inside `build_instrument_context`, and inside each risk-debater node. The cache hides this, but debaters now depend on yfinance. Berkshire's design, which resolves identity once in `init_run` and injects text, is cleaner.
4. **Weight-scale heuristic.** `_normalize_weight_pct` multiplies by 100 any value below 1.5 (`yfinance_etf.py:112-126`). A weight already in percent form but below 1.5% (for example 1.2) becomes 120%. Current yfinance returns decimals: live `Holding Percent` for SPY and EIMI.L comes back as 0.08, 0.13 and so on. The branch is therefore latent, but wrong when it fires.
5. **Constituent symbol rewrite.** A bare numeric symbol of up to 5 digits always becomes `NNNNN.HK` (`yfinance_etf.py:210`). A bare Japanese or Taiwanese code would be sent to the wrong exchange. For EIMI.L, yfinance already returns `2330.TW` and `005930.KQ`, so this only bites when the suffix is missing.
6. **Coverage is uneven, and the PR does not say so.** A live check on 2026-09-25 gave these results. GLD: `quoteType=ETF`, category "Commodities Focused", `top_holdings` empty. AGG: a single cash-fund row at 3%, so the "concentration" block would call a 13,000-bond fund concentrated in one money-market fund. SPY and EIMI.L: good top-10 lists. Concentration metrics over a partial top-N slice (the PR itself notes they cover only the visible slice) mislead for bond and commodity ETFs. The prompt should state what the numbers cover.
7. Minor: `default_config.py` says `etf_data` "Options: yfinance", although Alpha Vantage is wired. Wrapping `VENDOR_METHODS` in place at import time is idempotent only because the module is imported once.

The leveraged/inverse detection and warning are correct and useful. Failure behaviour elsewhere is good: errors come back as strings, and `funds_data` is treated as optional.

## Value to Berkshire

**High relative to the cost, for this user.** Four of the watchlist instruments (GLD, SPY, AGG, EIMI.L) are ETFs, and a tick analyses holdings plus the watchlist (D4, REQ-SCHED-01). Today Berkshire does worse than the PR for them:

- `detect_asset_type` knows only `crypto` and `stock` (`berkshire/pipeline.py:48-49`). `etoro.asset_kind` maps eToro ETF instruments (asset type 6, the defined but unused `ASSET_ETF` in `berkshire/etoro.py:14`) to `"stock"` (`berkshire/etoro.py:114-115`).
- `data.profile` already reads `quoteType` into `identity["quote_type"]` (`berkshire/data.py:207`), but nothing uses it. `instrument_context` labels the fund "Company: SPDR Gold Shares" (`berkshire/pipeline.py:73-74`).
- The Fundamentals Analyst persona (`agents/fundamentals-analyst.md:8-12`) asks for "company financials" and "intrinsic value drivers". For GLD, `tool_fundamentals` returns a "company fundamentals" table with just `priceToBook 2.31`, `dividendYield 0.0` and 52-week range, and the statements return "No balance_sheet data". This invites exactly the hallucination the PR targets.
- The risk debaters get no ETF axes. For AGG (duration/credit), GLD (commodity, no yield, trust structure) and EIMI.L (EM, USD-listed-in-London, currency), the relevant risks are fund-level, not company-level.

This improves decision quality and honesty about data. It also makes scheduled ticks more robust, because a whole analyst no longer spends its effort on empty statements. It is not plumbing.

Not worth taking: the **drill-down**. It costs 2×N data calls per run and uses current-only fundamentals, and the News Analyst can already search constituent news. Also skip the **Alpha Vantage path** (D3 says yfinance, eToro and web search) and the **placeholder decorators**. Berkshire tools are called by a subagent that reads its persona, so a mode-specific tool list in the prompt is simpler than wrapping vendor functions.

## Proposed Berkshire change

Add an `etf` asset mode alongside `crypto`:

1. **Detection (engine).** `detect_asset_type` → `etf` when `identity.quote_type == "ETF"`. `etoro.asset_kind` → `etf` for `ASSET_ETF`, so a tick classifies without a network call. `init_run` resolves identity before choosing the mode (it currently computes `asset_type` first, at `berkshire/pipeline.py:150`). If identity fails, the fallback is `stock`, as today. Add `etf` to the `--asset-type` choices (`berkshire/cli.py:317`).
2. **Context (engine).** In `instrument_context`, for `etf`: say "Fund:" instead of "Company:", add "treat it as a fund, not a company; analyse strategy/underlying exposure, holdings concentration, expense ratio, AUM/liquidity, premium/discount, structure". When `category` starts with `Trading--` and contains Leveraged or Inverse, add the daily-reset decay warning. Add the ETF risk-axes paragraph to the risk debaters' context (the text is short enough to write fresh; no copying needed).
3. **Data tool.** `berkshire data --run RUN etf_profile SYMBOL`: profile fields, sector and asset-class weights, top-10 holdings with weights normalised from yfinance's decimal form (no 1.5 heuristic), and the concentration block. Also:
   - The block is labelled "top-N shown only".
   - Holdings that are empty or a single cash line are reported as "holdings not disclosed by source".
   - The CURRENT_NOTE caveat applies whenever `trade_date < today` (REQ-DATA-07).
   - Errors come back as strings (REQ-DATA-06).
4. **Persona.** In `agents/fundamentals-analyst.md`, add an ETF branch: when the prompt says it is an ETF, use `etf_profile`, skip statements and insider data, and report fund dimensions. Keep the Fundamentals Analyst selected; unlike crypto, a fund does have fundamentals.
5. **Requirements.**
   - Add REQ-FLOW-10: ETF mode detected from `quoteType` or eToro asset type 6, with fund prompts and the ETF risk axes.
   - Amend REQ-IF-04 to mention ETF detection.
   - Amend REQ-ROLE-03 so the Fundamentals data access includes the ETF profile.
   - Add REQ-DATA-08 for `etf_profile`, with a current-data label and a partial-coverage note.
   - Update REQ-CTX-01 wording: "Company" becomes "Fund" for ETFs.
   - Add a ledger row in `docs/upstream.md`.
6. **Tests.**
   - Detection from identity and from eToro type.
   - Instrument context for an ETF and a leveraged ETF.
   - `etf_profile` rendering with mocked `funds_data`, covering empty holdings (GLD), a single cash row (AGG), and a past-date caveat.
   - A traceability entry.

## Effort and risk

- **Effort: M** (about a day): roughly 60-100 lines of engine code across `pipeline.py`, `etoro.py`, `data.py` and `cli.py`, one persona edit, about 6-8 tests, and doc rows.
- **Risk: low to medium.**
  - The mode switch changes the run `signature`, so in-flight checkpoints for ETF tickers restart once.
  - Detection depends on yfinance `quoteType`. A misclassification in either direction only changes prompts, never the risk gate or order sizing.
  - Some ETF data is thin (GLD and AGG holdings). That is why the "not disclosed / current only" labels matter more than the metrics themselves.

## Open questions

- Should leveraged or inverse ETFs also get a risk-gate rule, such as a lower max weight or no multi-day holds, rather than only a prompt warning? That would touch the configurable limits (D5).
- For EIMI.L (LSE-listed, USD-denominated), should the context also note trading currency versus base currency? That is FX exposure that the PR ignores.
- Should `etf_profile` be exposed to the Market or News analysts too, for sector-momentum framing, or kept to Fundamentals only as upstream does? Keeping it to Fundamentals preserves REQ-ROLE-03 parity.
- Commodity and bond ETFs (GLD, AGG) gain little from holdings data. Would a small static "underlying exposure" hint from `category`, such as "Commodities Focused" or "Intermediate Core Bond", serve them better than holdings?
