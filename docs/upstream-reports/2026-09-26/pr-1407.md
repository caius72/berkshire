# PR #1407: Sentiment Analyst: let the caller supply its data sources

Head `1ca16a2df0e7` · author mihaidimoiu · opened 2026-09-24 · +334/-40 · 20 files · base `main`
(head branch is the fork's `main`)

## Summary

**Verdict: decline.** The hook is LangGraph dependency-injection plumbing. It lets a caller pass in
pre-recorded sentiment inputs, but it supplies no recorded data. Berkshire has no such archive, and its
Sentiment Analyst is a subagent that fetches its own sources. The honest point-in-time handling that
matters (window trimming, "current" labels, a PIT Bluesky query, the backtest caveat) is already in
Berkshire. The PR has also grown to bundle three unrelated features that its description does not
mention.

## What it does

The title feature is small. The node's three inline fetches (Yahoo news, StockTwits, Reddit, with the
Jev screen and #1220 window trimming) move unchanged into `fetch_sentiment_sources`
(`tradingagents/agents/analysts/sentiment_analyst.py:56-72`). `create_sentiment_analyst` gains a
`sources: SourceFetcher` parameter that defaults to that function (`:75`), and the node calls
`sources(ticker, start_date, end_date)` (`:93`), which returns a `SentimentSources(news, stocktwits,
reddit)` NamedTuple. `TradingAgentsGraph` and `GraphSetup` pass through a `sentiment_sources` argument
(`tradingagents/graph/trading_graph.py:56`, `tradingagents/graph/setup.py:63,90`).

The problem is real. Upstream's sentiment node fetches outside the tool layer, so replacing the tools
cannot redirect it. Every run therefore makes live requests that a frozen-dataset or replayed backtest
cannot control. #1220 (closed) made historical runs trim social posts to the window. Because the
feeds are not archived, a past date usually gets an empty or placeholder block. This hook lets a caller
who recorded posts at the time supply them.

The head branch is the author's fork `main`, and five later commits have been pushed onto it. The
diff now also contains:

- **`tool_nodes`**: replace the ToolNode of any analyst (`graph/setup.py:112`, `trading_graph.py`). This
  is the same replay idea for the tool-using analysts.
- **`prompt_extra`**: per-agent free-text instructions appended to all 12 prompts from
  `config["prompt_extra"]` (`agents/context.py:41-53`, `default_config.py:116`).
- **Portfolio Manager confidence (0-100 %), Key Reasons, and What Would Prove It Wrong**, added to the
  prompt, schema and renderer (`agents/managers/portfolio_manager.py:77-81`, `agents/schemas.py:240-330`),
  plus `extract_confidence` (`agents/rating.py:98-118`).

The PR description covers only the sources hook.

## Soundness

The sources hook itself is correct and behaviour-preserving. The default reproduces the old fetch
exactly, and the fixture-patched test confirms that the default returns the same blocks. Weaknesses:

- **The caller's fetcher is unguarded.** The default's "never raises, always returns a string"
  contract is documented only on the default (`sentiment_analyst.py:57-61`). An exception from a
  caller-supplied fetcher at `:93` propagates and fails the analyst node. The node could catch the
  exception and fall back to a placeholder. It does not.
- **A custom source skips the Jev screen, and the skip is undocumented.** The screen is built inside
  the default fetcher (`:65`), so replaced sources are never screened. That is probably intended, but
  it is not stated.
- **Point-in-time safety is the caller's job.** The hook does not check that supplied items fall inside
  `start_date..end_date`, and the prompt still presents the blocks as "past 7 days". A careless
  recorded corpus reintroduces the #1220 look-ahead.
- **The fetcher gets only `(ticker, start, end)`.** It receives no asset type and no instrument
  identity, so a recorded corpus cannot tell a crypto pair from an equity.
- **The tests are thin on the window.** `test_default_sources_fetch_live` checks only the returned
  blocks, not the dates passed to the fetchers, so a regression that dropped the #1220 window would
  pass it. `test_caller_supplied_sources_replace_the_live_fetch` asserts only `start < end`, not the
  7-day window.

Bundled extras:

- **Confidence parsing is inconsistent.** `_coerce_percent("0.6%")` strips the `%` and then treats 0.6
  as a fraction, which gives 60 (`agents/schemas.py:317,324`). `extract_confidence("**Confidence**:
  0.6%")` reads 1, because the `%` suppresses the fraction rule (`agents/rating.py:113`). The two
  parsers for the same field disagree.
- **Nothing consumes the confidence yet.** `extract_confidence` has no caller outside the tests, and
  confidence does not reach the decision log, reflection or backtest scoring. It is display-only.
- **`prompt_extra` is an injection surface into every prompt**, including the judges'. It is harmless
  as local config, but it also changes prompts without changing any run signature.

## Quality and maturity

- It is mergeable against current `main` (`35543d0`), has no CI checks reported, and has no reviews or
  comments.
- Tests were added for each feature: two for the sources hook, plus confidence and PM-section tests.
  The author reports 1006 passing.
- Six commits sit on a fork `main` that keeps receiving unrelated work: "Add confidence output",
  "prompt_extra", "Fix graph", and PM key reasons were pushed on 2026-09-26. The PR is therefore
  unstable, and its scope no longer matches its title.
- A maintainer is unlikely to merge it as one PR. The likely outcome is a request to split it. The
  sources hook alone is small and coherent and would plausibly merge after a split.

## Value to Berkshire

The hook itself has little value for Berkshire:

- **The architecture does not match.** Upstream needs an injection point because its node fetches
  inside Python. Berkshire's Sentiment Analyst is a subagent whose persona tells it to fetch
  (`agents/sentiment-analyst.md:10-13`). The engine never holds the social blocks. The Berkshire
  equivalent would be engine-side pre-fetch or replay: a `berkshire data social` tool that reads a
  recorded corpus from the backtest home and is written into the sentiment prompt. That is a new
  subsystem, not a hook.
- **There is no data to feed it.** The hook is only as good as a recorded archive, and neither
  upstream nor Berkshire has one. Building a recorder would mean live ticks capture the raw StockTwits,
  Reddit and news blocks per ticker and date, and backtests replay them. It pays off only after months
  of recording, and only for re-running past dates under a changed model or prompt. Berkshire
  backtests (`berkshire/backtest.py`, REQ-BT-01..04) do not need that today.
- **Berkshire already covers the honesty side.** `berkshire data news` is window-trimmed and clamped
  (REQ-DATA-01, REQ-DATA-05). Past-dated runs get the point-in-time rule, which labels social and web
  evidence as current (`berkshire/pipeline.py:270-272`, REQ-DATA-07). The persona drops posts after the
  date and says the read is not point-in-time (`agents/sentiment-analyst.md:28`). Bluesky is queried
  with a since/until window (PR #922, adapted). The backtest summary states that social sources are not
  archived (`berkshire/backtest.py:88`). On grounding and honesty, Berkshire is already at least as good
  as upstream with this PR.

The bundled extras belong to other topics and should not be decided on this PR:

- **`prompt_extra`**: decline. In Berkshire the personas are plain `agents/*.md` files the user can
  edit directly, and hidden per-agent prompt text would bypass the checkpoint signature (REQ-CKPT-02).
- **`tool_nodes`**: not applicable. Berkshire's tools are the `berkshire data` CLI, not ToolNodes.
- **PM Key Reasons, What Would Prove It Wrong, and a calibrated confidence**: potentially valuable to
  Berkshire's learning loop. Invalidation conditions would give the Reflector a concrete test for
  whether the thesis broke (REQ-MEM-04/08), and a stated probability could be scored for calibration in
  the backtest summary (REQ-BT-03). Here, though, nothing consumes them and the parsing is
  inconsistent. See Open questions.

## Proposed Berkshire change

None. The mechanism is upstream graph plumbing with no counterpart in Berkshire's subagent design. The
reproducibility it enables depends on an archive neither project has, and Berkshire's point-in-time
labelling and backtest caveat already cover the honesty concern. No `REQ-*` changes.

## Effort and risk

- No change, so no effort (S).
- For reference, a Berkshire replay path would cost about L. It needs a recorder in the tick, a corpus
  format, a `berkshire data social` reader with window checks, persona and prompt changes, and new
  REQ-DATA/REQ-BT rows. The risk would be stale or out-of-window replayed posts presented as point-in-time.

## Open questions

- If the author splits the PM confidence, Key Reasons and invalidation fields into their own PR, scout
  that PR on its own merits. The question for Berkshire is whether invalidation conditions should feed
  the Reflector and a stated probability should feed a calibration score in the backtest summary.
- Would Berkshire ever want to re-run past dates with the social inputs the live tick actually saw?
  If so, the cheap first step is for ticks to persist the raw sentiment inputs next to
  `1_analysts/sentiment.md`, not an injection hook.
