## Summary

**Verdict: decline.** The PR feeds a hand-written JSON list of investment heuristics to every downstream role through an extra LLM node. Berkshire's rule is that roles decide only on dated, verifiable evidence, and these rules are undated priors that nothing checks. On top of that, the implementation loads the example rules by default and cuts the judges' debate history short.

## What it does

- **Loader** (`tradingagents/agents/utils/factor_rules.py`): a new module that reads a JSON rule list. Each rule has `name`, `signal`, `weight`, `thesis`, `conditions` and `rationale`.
- **Lookup order:** `config["factor_rules_path"]`, then `TRADINGAGENTS_FACTOR_RULES_PATH`, then `<project_dir>/examples/factor_rules.json`, then `<project_dir>/factor_rules.json`.
- **Summary:** the loader writes the rules out as text, with a count of bullish, bearish and neutral rules.
- **Factor Rule Analyst** (`tradingagents/agents/analysts/factor_rule_analyst.py`): a new node that makes one quick-model call to restate that summary as a report. It has no tools and no data.
- **Wiring:** the resulting `factor_rules_report` goes into the Bull and Bear researchers, the Research Manager, the Trader and the Risk Manager. It is also added to the text each of them uses to look up past memories.

The problem it targets is having no place for a user's own "house view" (valuation overlays, balance-sheet preferences, sector biases) other than editing prompts. No issue is referenced.

The PR also carries three unrelated changes:
- a `default_headers` passthrough for the OpenAI client (`openai_client.py:64`);
- vendor fallback on *any* exception instead of only rate limits (`dataflows/interface.py:167`);
- a rewrite of the researcher and manager prompts into system and user messages, with each input passed through a new `_sanitize_text`. The rewrite drops several directives from the Risk Manager prompt.

## Soundness

Concrete bugs:

1. **Example rules are applied to every run by default.**
   - `trading_graph.py:48` adds `"factor_rules"` to the default `selected_analysts`.
   - `project_dir` is the package directory (`default_config.py:4`), and the PR ships `tradingagents/examples/factor_rules.json`, which is the third candidate path (`factor_rules.py:30`).
   - The result: an unconfigured run of any ticker gets "AI capex acceleration: bullish, high weight" and "Balance sheet resilience: bullish" injected into the debate, the Trader and the Risk Manager. That is a silent bullish tilt, and it contradicts the "optional, backward-compatible" claim. Copilot flagged this, and it was never fixed.
2. **The user's own rule file is silently replaced by the example.**
   - The path-traversal fix (`factor_rules.py:14-44`) keeps only files named exactly `factor_rules.json` inside `project_dir` or `project_dir/examples`, which for a pip install means inside site-packages.
   - An explicit path anywhere else (for example `~/rules/factor_rules.json`) is dropped at `:44`. The "missing explicit path" guard at `:64` then never fires, because the path is no longer among the candidates. The shipped example loads instead, with no warning.
   - The test `test_outside_project_rule_path_is_rejected` passes only because its temporary project directory has no `examples/` file, so it hides the bug.
3. **The judges lose the end of the debate.**
   - `_sanitize_text` returns `text[:12000]` (`research_manager.py:5-8`), and it is applied to the full debate `history` in the Research Manager (`research_manager.py:53`), the Risk Manager (`risk_manager.py:49`) and the Bull Researcher (`bull_researcher.py:49`), and to the trader plan (`risk_manager.py:44`).
   - Truncation keeps the *start* of the text. From about three rounds on, the judges never see the latest arguments, and nothing tells them the text was cut.
   - This is a regression in the core pipeline that is unrelated to factor rules.
4. **Point-in-time leak.** Rules are not dated and not tied to a ticker or sector: every rule goes to every instrument on every date. In a backtest, heuristics written today with hindsight (for example "AI capex acceleration") steer decisions dated before anyone could have held that view. This is look-ahead bias that no data clamp can catch.
5. **Smaller problems:**
   - An invalid JSON file raises from inside a graph node (`factor_rules.py:69`) and aborts the run instead of degrading.
   - The constant rule text is appended to every memory-retrieval query (`trader.py:16`, and the matching lines in the researchers and managers), which blurs similarity matching.
   - The Trader gets the report without the untrusted-data fences that the other roles get (`trader.py:28`).
   - Vendor fallback now also swallows programming errors (`interface.py:167`).

The "untrusted data" wrapping is a reasonable touch. However, restating a static JSON through an LLM adds a call and a chance of drift, and adds no information: the deterministic summary could go straight into the prompts.

## Value to Berkshire

The value is low, and the idea cuts against Berkshire's design:

- **Evidence-only roles.** REQ-ROLE-04 says researchers, managers and the Trader decide only on the evidence in their prompt. Unverified user priors placed alongside that evidence make grounding weaker, not stronger. The analyst reports are backed by date-clamped tools (REQ-DATA-01, REQ-DATA-07), and these rules would come in with none of that discipline.
- **Point-in-time safety.** Berkshire goes out of its way to keep information from after the trade date out of past-dated runs and backtests: lessons are filtered by resolution date (REQ-MEM-05), and the current profile is withheld on past dates (REQ-DATA-07). Undated rules would bring the look-ahead back.
- **Hard constraints already have a home.** House rules that are real constraints (excluded sectors, concentration caps, no leverage) belong in the deterministic risk gate. They are already partly there as REQ-RISK-02, REQ-RISK-04 and REQ-RISK-08, where they are enforced rather than argued over.
- **Soft preferences are a user decision Berkshire has not taken.** A soft "tilt toward net-cash companies" is a new product decision, and it has not been requested. Berkshire has no counterpart today: nothing in `berkshire/`, `agents/` or `skills/` injects user heuristics.

Berkshire is already better placed than this PR on the adjacent concerns:
- missing context is marked explicitly (REQ-CTX-02);
- prompts are assembled deterministically in `berkshire/pipeline.py:263`;
- nothing truncates debate history silently.

## Proposed Berkshire change

None. The mechanism adds unverifiable priors and a look-ahead path, and its one real need, hard constraints, is better served by the risk gate.

If the user ever asks for a house view, it should be built the Berkshire way rather than taken from this PR:
- a **dated** `mandate` text in `~/.berkshire/config.json`;
- given only to the Portfolio Manager, in `build_prompt` (`berkshire/pipeline.py:263`), labelled as the owner's preference rather than evidence;
- withheld from runs dated before the mandate's `since` date;
- included in the run signature.

That would need new REQ-CTX and REQ-BT rows. Hard constraints would instead extend REQ-RISK.

## Effort and risk

- **Effort:** M (about a day) if the mandate variant above is ever requested. It touches `config.py`, `pipeline.py` and the Portfolio Manager persona, adds one REQ-CTX row and amends REQ-BT, and needs tests for the date gating and the run signature.
- **Risk:** it moves the Portfolio Manager away from evidence-only decisions, and a mandate that is not dated correctly would contaminate backtests.
- **Taking this PR's approach as it stands:** high risk, because of the default-on bias and the silently truncated debate history.
