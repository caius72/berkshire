# PR #702: feat(dataflows): add SearXNG as a self-hosted news vendor (#699)

Head `95b4dd68a8b8`, by armaansharmaa, opened 2026-05-03, last touched 2026-05-05. +384 / -4 across 5 files. Closes issue #699.

## Summary

**Verdict: decline.** It adds a self-hosted metasearch server as a news source, but its time filter counts back from today, not from the analysis date, and it keeps undated results. That makes it unsafe for past dates. Berkshire's analysts already get the same coverage with no extra server: Claude WebSearch, windowed Google News in `news`, and Reddit, StockTwits and Bluesky through WebFetch.

## What it does

A new vendor module `tradingagents/dataflows/searxng.py` sends four queries for each ticker to a SearXNG JSON endpoint (`SEARXNG_BASE_URL`, default `http://localhost:8888`): stock news, `<company> earnings revenue`, analyst upgrades and downgrades, and `<ticker> site:reddit.com OR site:x.com` (`searxng.py:62-67`). It then deduplicates by URL, filters by date, caps the list at 20 and formats it in the same shape as the yfinance output. Global news runs four fixed macro queries (`searxng.py:183-188`). The module is registered for `get_news` and `get_global_news`, and `SearxngUnavailableError` is added to the router's fallback `except` (`interface.py:167`), so `"searxng,yfinance"` falls back to Yahoo when the SearXNG server cannot be reached.

The problem it targets (#699, following #557) is that upstream's Social Media Analyst had no social data: it re-read the same ~20 Yahoo articles. The PR's answer is one self-hosted aggregator over 70+ engines, including Reddit and X.

## Soundness

- **The search window is wrong for any date except today.** `_search` passes SearXNG `time_range="month"` / `"week"` (`searxng.py:166`, `searxng.py:192`). SearXNG measures that range back from now, not from `end_date`. For a past date, the query returns the latest month of results, whatever the analysis date. The date filter then drops the dated ones and keeps the rest.
- **Undated results leak future information.** `_dedupe_and_filter` keeps every result without a parseable `publishedDate` (`searxng.py:124-126`). The query uses `categories: "news,general"` (`searxng.py:78`), and general web results are mostly undated. Together with the previous point, a backtest mostly sees undated pages from today's index. That is the look-ahead leak upstream later closed in its own rule: `tradingagents/dataflows/date_window.py` (`in_window`) keeps undated items only when the window reaches the present (#1126, #1220). Berkshire has the same rule at `berkshire/data.py:635-640`.
- **Timezone and boundary.** `_parse_published` removes the offset without converting to UTC (`searxng.py:97`, `searxng.py:99`), so `+05:00` timestamps shift by hours. The upper bound `published <= end + 1 day` (`searxng.py:125`) includes an item stamped exactly at midnight after the end date. Upstream's `in_window` uses a half-open, UTC-normalised window for this reason.
- **No coverage marker.** When the window contains no dated item, the function returns `"No news found for …"` (`searxng.py:169-170`). That reads as an absence of news, when the source simply never looked at that window. Upstream's `coverage_gap` and Berkshire's REQ-DATA-05 marker ("unavailable, not an absence") exist to prevent exactly this.
- **Failure handling.** If any one of the four facet queries fails, the whole call raises (`searxng.py:90`), and the results of the other three are thrown away in favour of the fallback. Fallback happens only when a later vendor is configured; `news_data: "searxng"` alone ends in `RuntimeError`. Stock SearXNG ships with `formats: [html]`, so the JSON API returns 403 until the operator enables it. The PR does not document this, so a new user silently falls back to Yahoo every time. `_company_name` is `lru_cache`d including `None` (`searxng.py:35-52`), so one transient yfinance failure keeps the whole process on ticker-only queries.
- **The social facet is weak.** Whether `site:a OR site:b` works depends on the engine, and search engines index very little of X. The "real Reddit/X sentiment" is therefore a few search snippets with no post bodies, no stance tags, no dates, and no screening for posts that are actually about the instrument.

## Quality and maturity

The PR adds 6 unit tests with mocked HTTP; they cover formatting, dedup, the date filter, the result cap, the name cache and router fallback. It has no CI runs (`statusCheckRollup` is empty), and the smoke test against a real SearXNG instance is left unchecked. The only review is gemini-code-assist's bot review, and the author has pinged the maintainer since then with no reply. The PR is **CONFLICTING**, and cannot be rebased as it stands. Upstream has since removed `tradingagents/dataflows/interface.py` (c42a2f2) and split vendors into `dataflows/vendors/*` with `router.py`, `errors.py` and `date_window.py`. Upstream has also since added its own Reddit and StockTwits vendors (`vendors/reddit.py`, `vendors/stocktwits.py`), which removes most of the motivation in #699. The chance of a merge in this form is low. If it is revived, it has to be rewritten against `router.py` and `date_window.in_window`.

## Value to Berkshire

Little, and in one respect negative:

- **Coverage is already there.** REQ-ROLE-03 gives the News and Sentiment analysts WebSearch and WebFetch. WebSearch is already a multi-engine web search with no key and no server to run. REQ-DATA-05 merges Google News into `news` with `after:`/`before:` operators, so Google's own index does the windowing (`berkshire/data.py:699-752`). SearXNG can't do that. The Sentiment Analyst fetches Reddit and StockTwits JSON directly and queries Bluesky within the window (`agents/sentiment-analyst.md:11-13`), screens posts for topic and counts stance (`agents/sentiment-analyst.md:15`). That is a stronger social read than search snippets.
- **Honesty about data would get worse.** Berkshire's REQ-DATA-05/07 rules (undated items only on live runs, a coverage-gap marker, labelling current-index sources as current) would each have to be re-imposed on the PR's output. Its range counts back from now, so it would add nothing point-in-time.
- **It does not fit the deployment.** Berkshire is a Claude Code plugin whose data comes from bundled yfinance, eToro and WebSearch/WebFetch (decision D3). A Docker SearXNG server on localhost would be a new moving part for a scheduled `/loop` tick, and when it is down the run silently degrades to the fallback.

Berkshire is already better than this PR on every axis it touches.

## Proposed Berkshire change

None. The idea is fully covered by REQ-DATA-05 (Google News in `news`), REQ-DATA-07 (current-index labelling) and REQ-ROLE-03 (WebSearch, WebFetch and social sources). The one reusable idea is small: the faceted queries (earnings, analyst upgrades and downgrades). Berkshire's `news` searches Google News by company name only, and the News Analyst can already run those facets through WebSearch. This does not need an engine change.

## Effort and risk

Adopting it would take effort M: a vendor module, a config key, fallback wiring, point-in-time and coverage-marker handling, and tests. It would add an operational dependency, and past-dated runs would carry look-ahead risk unless the undated-result rule were enforced. Declining costs nothing.

## Open questions

- Should the News Analyst persona explicitly suggest WebSearch facets for analyst rating changes and earnings reactions within the window? That would be a prompt tweak, and it would only be worth it if reports show those events being missed.
- If upstream ever lands a reworked SearXNG vendor that goes through `date_window.in_window` and `coverage_gap`, re-check it only for its query design, not as a new source.
