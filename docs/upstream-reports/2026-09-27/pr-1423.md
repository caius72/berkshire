# PR #1423: Polish CLI dashboard and add VS Code launch config

Head `1c134c223173`, author hunters1011-ctrl, opened 2026-09-27, +148 / -96 across 4 files.

## Summary

**Verdict: decline.** This PR only restyles TradingAgents' Rich live panel and adds an unrelated personal IDE file. Berkshire's views already show the same run context and a team roll-up, and they keep the per-agent detail that this PR removes.

## What it does

- **Header.** `cli/display.py:185-214` replaces the welcome banner with a one-line header: `TAURIC / TRADINGAGENTS`, then `● LIVE / ticker / date / PROVIDER`. The values come from a new `MessageBuffer.run_context` dict. `cli/run.py:117-122` fills it with `ticker`, `analysis_date` and `config["llm_provider"]`.
- **Progress panel.** `cli/display.py:235-248` collapses it from one row per agent (with a spinner) to one row per team. Each team shows `● ACTIVE`, `✓ DONE`, `n/m DONE` or `○ QUEUED`.
- **Activity and footer.** The messages table turns into a two-column grid with the message type coloured inline (`cli/display.py:287-296`), and it keeps 8 messages instead of 12 (`:281`). The footer stats move into a 3-column label/value grid (`:364-382`), so the footer grows to 4 lines (`:166`). Panel padding goes from `(1, 2)` to `(0, 1)`.
- **Launch config.** It adds `.vscode/launch.json`, which launches Microsoft Edge at `http://localhost:8080`.
- **Test.** `tests/test_cli_display.py:95-114` renders the layout at 80 and 120 columns and checks that eight labels appear.

The problem it solves is cosmetic: the panel is too dense and too tall for an 80-column terminal. It is not tied to an issue.

## Soundness

There is no decision, data or look-ahead impact, because only presentation changes. Specific problems:

- **Per-agent visibility is lost.** `cli/display.py:238-248` reduces each team to one status. During the risk debate (`cli/run.py` sets Aggressive, Conservative and Neutral to in-progress in turn) and during the analyst phase, the panel now says only "ACTIVE" and no longer shows *which* agent is working. Upstream's panel exists to show that, and the removed spinner was the only per-agent sign that the run is alive.
- **The `error` status gets no branch.** The old code coloured `error` red. The roll-up has no branch for it, so a team with a failed agent would show `○ QUEUED` or `n/m DONE`. Nothing upstream sets `"error"` today (`update_agent_status` is only called with pending, in_progress and completed), so this has no effect now, but it removes a hook that was there on purpose.
- **Two ways to set the same state.** `init_for_analysis(..., context=None)` (`cli/display.py:65,72`) gains a `context` parameter that only the test uses. The production path in `cli/run.py:117-122` ignores the parameter and assigns `message_buffer.run_context` directly afterwards.
- **Shared test state.** The test (`tests/test_cli_display.py:98`) changes the module-global `message_buffer` and never resets it, which can make other tests depend on run order.
- **`.vscode/launch.json` does not fit the project.** Nothing in TradingAgents serves on port 8080, and the file is the contributor's own editor setup. A maintainer would ask for it to be removed.
- **Tests not run here.** The auto-mode permission check blocked running the PR's tests locally, so this review is based on reading the code. The rendering test only checks that labels are present, not the layout.

## Value to Berkshire

None that transfers. The PR does nothing for decision quality, grounding, honesty about data, learning from outcomes, robustness of scheduled ticks, or risk control. It is CLI polish only. On each idea, Berkshire already has an equivalent or better:

- **Run context in the header.** Both Berkshire views already show it. The TUI summary line has ticker, date, asset type, stopped state, signal, done/total agents and a warning count (`berkshire/tui.py:199-202`). The web run view shows the same through `/api/runs/<ticker>/<date>`, built by `pipeline.summary` in `berkshire/server.py:128`.
- **Team roll-up.** The web "floor" (`webui/src/App.jsx:40-63`) already reduces each team to done, active or pending, *and* keeps one seat per agent with its own status. That is what this PR should have done.
- **Per-agent status by team.** The TUI keeps the per-agent table grouped by team (`berkshire/tui.py:155,203-208`). REQ-UI-05 (`docs/requirements.md:216`) requires "every agent's status by team", and this PR's layout would fail that requirement.
- **LLM calls and token counts in the footer.** These come from a LangChain callback handler. Berkshire's roles are Claude Code subagents, so there is no equivalent counter to show without new plumbing. It would also add little to a human-approved, demo-first flow.
- **VS Code launch file.** Not applicable.
