# PR #581: feat: configurable metrics in report output (#545)

Head `9db0a0a04082` · author claytonbrown · opened 2026-04-20, last updated 2026-04-28 · +201/-40 in 3 files · not draft · mergeable: CONFLICTING

## Summary

**Verdict: decline.** The PR does not deliver what its issue asks (financial metrics in a table); it adds on/off switches that hide whole agent reports from the CLI output, which is display chrome and, for Berkshire, would weaken the audit trail of a decision.

## What it does

- Adds `tradingagents/metrics_config.py`: a nested `TypedDict` (`analysts`, `research`, `trading`, `risk`, `portfolio`) of 12 booleans, one per agent report, all `True` by default, plus `is_metric_enabled()` (missing key means enabled), `list_all_metrics()`, and `parse_metrics_flag()`, which turns `--metrics a.b,c.d` into an allow-list and rejects unknown keys (`metrics_config.py:72-118`).
- Registers the default in `DEFAULT_CONFIG["metrics_config"]` (`default_config.py`), and adds `--metrics` / `--list-metrics` to `analyze` in `cli/main.py`.
- Wraps each section in the CLI's final live report, `save_report_to_disk` and `display_complete_report` with an `is_metric_enabled` check (`cli/main.py:192-230`, `645-733`, `736-796`).

The agents still run and the LLM still pays for every report; only what gets written to the report tree and printed on screen changes. "Metrics" here means whole agent reports, not figures.

Issue #545 ("Customizable table of metrics") asks for something else: save the financial extracts in the final report, add user-chosen derived ratios (for example price to owner earnings), and link to the SEC filings. The PR does none of that, yet says "Closes #545". The issue has no comments and no maintainer response.

## Soundness

- **Inconsistent filtering (bug).** `_update_final_report` gates every section except the research one: `cli/main.py:219` still appends `investment_plan` unconditionally. During the run the CLI writes the bull and bear debate text into `investment_plan` (`cli/main.py:1102`, `1106`), so `--metrics analysts.market_report` still shows the bull/bear debate in the live final report, while `save_report_to_disk` and `display_complete_report` hide it. The three output paths do not agree.
- **The key is reused, with no key of its own.** The Portfolio Manager block is gated by `portfolio.final_trade_decision`, but what gets written is `risk_debate_state.judge_decision` (`cli/main.py:724`, `793`). This works only because the two strings hold the same text.
- **Hiding the decision is allowed.** A `--metrics` list that leaves out `portfolio.final_trade_decision` writes a `complete_report.md` with no decision section. `--metrics ","` disables everything and gives a report that is only a header. No guard, no warning.
- **The config only works from the CLI.** `metrics_config` sits in `DEFAULT_CONFIG`, but `TradingAgentsGraph` never reads it, and no env or file override exists. A library user who sets it gets no effect. The state log JSON is still written in full, so nothing is actually hidden: it is a presentation filter only.
- **Minor.** `DEFAULT_CONFIG` now holds a reference to the module-level `DEFAULT_METRICS_CONFIG` dict, and `run_analysis` makes only a shallow copy (`cli/main.py:942`). It is safe today only because nothing mutates it. `default_config.py` now imports a CLI-facing module at import time.
- Point-in-time and look-ahead: not affected. The PR touches no data and no prompts.

## Value to Berkshire

- **Decision quality, grounding, learning, risk:** none. It changes no agent input or output.
- **Honesty and audit:** negative. Berkshire treats the report tree as the record of why an order was proposed. REQ-RPT-01 requires all 12 files and sections I–V, and TST-RPT-01 checks exactly that. Letting a user drop the debate or the decision from `complete_report.md` removes the evidence behind an order that a human then approves (D2).
- **Presentation:** Berkshire already covers what a user would want from this. `report_sections()` (`berkshire/pipeline.py:454`) is the single list that the report tree and both views share. The dashboard and TUI (REQ-UI-05, REQ-UI-08) let the user pick which agent's report to read, and `complete_report.md` always carries the signal in its header (`berkshire/pipeline.py:484`), so there is nothing to hide the verdict from. Deselecting analysts (REQ-FLOW-05) already skips their reports, and saves the tokens the PR still spends.
- **The idea in issue #545 itself** (derived ratios and filing links in the fundamentals report) is closer to something Berkshire could use. Berkshire already computes P/E and P/B as of the trade date with their basis and date (REQ-DATA-08), and analysts end with a markdown table (REQ-ROLE-05). It does not compute owner earnings or link to SEC filings. That is a separate idea, and this PR does not advance it.

## Proposed Berkshire change

None. The PR only hides output, which conflicts with REQ-RPT-01 and the audit role of the report tree. Berkshire's views already let the user choose what to read without deleting it from the record.

## Effort and risk

Not applicable. Taking it would be about S (a filter over `report_sections()` plus a flag), but the cost would be a weaker audit record and an amendment to REQ-RPT-01. That is a bad trade.
