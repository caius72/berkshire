# PR #1429: feat: add NewsData, X, and Truth Social data sources

- Upstream: TauricResearch/TradingAgents#1429 by sivaborra, opened 2026-09-27
- Head: `e2ee70a1c4f1` (not a draft, `CONFLICTING`, no CI runs, no reviews or comments)
- Size: +981 / -24 across 23 files (3 new vendor modules, 1 new tool module, 3 new test files)

## Summary

**Verdict: decline.** None of the three sources works for a past-dated run, two of them cost money or are
blocked by default, and Berkshire's `news` tool already merges several providers with deduplication.
The only thing worth keeping is one line of prompt guidance: syndicated copies of one story are not
independent confirmation.

## What it does

1. **NewsData.io vendor** (`tradingagents/dataflows/newsdata_io.py`). It calls the `/api/1/market` endpoint
   once per tool call, with `q=<TICKER>` for ticker news (`newsdata_io.py:166`) and no query for global news
   (`newsdata_io.py:196`). It then filters the returned page to the analysis window. The request sets no
   `from_date`, `to_date` or `timeframe`, so it only ever sees the vendor's latest window.
2. **News aggregation in the router** (`tradingagents/dataflows/interface.py:106,256,287`). `get_news` and
   `get_global_news` stop using ordered first-success fallback. The router now calls every configured vendor
   and joins the results into labelled `## Provider:` blocks, with a "Provider availability" list for the
   vendors that failed (`interface.py:188`). The default chain becomes `newsdata,alpha_vantage,yfinance`
   (`default_config.py:144`).
3. **X recent search** (`tradingagents/dataflows/x_social.py`) through the official v2 `search/recent`
   endpoint, with a Bearer token and a cap of 30 posts. **Truth Social** (`truth_social.py`) fetches the
   latest 20 statuses of @realDonaldTrump from the official Mastodon-style endpoint. Both are exposed as
   News Analyst tools (`social_data_tools.py`), and both are also pre-fetched into every Sentiment Analyst
   prompt (`sentiment_analyst.py:85-86`). The prompts gain rules against double-counting syndicated
   stories, treating social posts as fact, or rolling Trump's posts into a crowd ratio.

The PR describes the problem as "more coverage". It references no issue.

## Soundness

**Point-in-time safety for past-dated runs.** All three sources return current items only. The PR filters
their output with the shared `in_window` / `coverage_gap` helpers, so nothing from the future leaks in.
But nothing useful gets through for a past date either:

- **NewsData**: the market endpoint serves the last 48 hours, and on the free plan the articles are
  delayed 12 hours with 10 per request. Any run dated more than about 2 days ago gets
  `NoMarketDataError`, after spending a credit. The PR's own test confirms this
  (`tests/test_newsdata_io.py`, `test_out_of_window_feed_is_no_data_not_current_news`). The endpoint does
  accept `from_date`/`to_date` on paid plans, but the adapter never sends them.
- **X**: recent search covers 7 days. Older windows are withheld without a request, which is correct.
  Backtests therefore always run without X while live runs have it, so a backtest does not see the same
  inputs a live run would.
- **Truth Social**: only the latest 20 statuses (`truth_social.py:41,57`). The archive holds about 160
  posts a week (measured 2026-09-20..26, 72 of them media-only with empty text), so 20 posts cover roughly
  one day. A 7-day window is therefore mostly unobserved even on a same-day run. The header's "returned
  coverage starts …" is the only hint of this, while the prompt still says "past 7 days". A run dated
  yesterday or earlier gets nothing.

**Concrete bugs and failure modes**

- `x_social.py:62,80-81`: `start_time` is clamped to exactly `now - 7 days` and then truncated to whole
  seconds. By the time the request arrives, that timestamp is already older than the 7 days X allows, and
  X rejects such a `start_time` with HTTP 400. The Sentiment Analyst always asks from `trade_date - 7 days`
  at midnight, which is earlier than `now - 7d`, so a same-day run always takes this path. It should get
  `<X unavailable: HTTP 400>` every time. The PR's test mocks `requests.get` and never checks `start_time`,
  and the author says no live X token was used. Fix: add a buffer of about 60 s to `recent_start`.
- `x_social.py:37`: the query `($SYM OR SYM)` matches the bare word, so tickers such as F, T, ON, ALL or A
  return unrelated posts, and each one is billed. The sentiment prompt has no rule to drop off-topic posts.
- `newsdata_io.py:166`: it uses the full-text `q` instead of the endpoint's `symbol` parameter, although
  the test is named `test_ticker_news_uses_symbol…`. The result is the same noise problem.
- The Truth Social endpoint returns **HTTP 403** from here: the Cloudflare block the author also hit
  (probed 2026-09-27). With the defaults, the source is unavailable.
- **Confidence regression**: sentiment rule 7 says any `<unavailable>` placeholder must be flagged as lower
  robustness in the `confidence` field. A default install has no X token and gets 403 from Truth Social,
  so every sentiment read gets marked down for sources the user never enabled. Berkshire deliberately does
  the opposite for Bluesky: an empty result never lowers confidence
  (`agents/sentiment-analyst.md:43`).
- **Aggregation cost**: with the new default chain, every news call reaches Alpha Vantage (25 requests a
  day on the free tier) and NewsData (200 credits a day) even when Yahoo already answered. A user without
  those keys gets two "not configured" status lines on every call. The header "All N successful configured
  provider(s) were queried" (`interface.py:193`) also reads wrong when some of them failed.
- Every sentiment prompt includes Trump's timeline whatever the ticker is. The prompt says to ignore
  unrelated posts, but the text still sits in the context of every run.

## Quality and maturity

- It adds 3 test files and updates the routing and date-enforcement tests, all mocked. There is no live
  check for X or Truth Social (stated in the PR). The one real bug above is exactly what a live check would
  have caught.
- There are no CI runs, reviews or maintainer response. The PR is `CONFLICTING`: it targets
  `dataflows/interface.py`, which upstream main has since replaced with `dataflows/router.py` and the
  `dataflows/vendors/` layout (`c42a2f2`, `6097b58`). It needs a real rebase, not only conflict fixes.
- Changing the default news chain to two keyed vendors changes behaviour for every upstream user.
- The chance it merges as-is is low. Earlier attempts at X or "more sources" (#231, #399, #1093) were
  closed. If any of it lands, the NewsData vendor is the most likely part, and without the default change.

## Value to Berkshire

- **Aggregation**: Berkshire already has this, and does it better. `berkshire/data.py:726-757`
  (`tool_news`) merges Yahoo Finance with Google News RSS. Google News is queried inside the window with
  `after:`/`before:`, so it covers past dates. Results are deduplicated by title, and one failing source
  adds an "unavailable" line (REQ-DATA-05). NewsData adds a keyed, 48-hour-only third feed and nothing a
  past-dated run or backtest can use.
- **X**: the only source here with a plausibly distinct signal, since fintwit volume is far larger than
  Bluesky's. But it costs $0.005 per post read (pay-per-use, no meaningful free tier since June 2026). That
  is about 30 to 90 billed reads per instrument per run, or roughly $0.15 to $0.45 per instrument, paid on
  every tick. X also gives nothing to backtests, which breaks the live/backtest input parity Berkshire's
  PIT rules protect (REQ-DATA-07). StockTwits (cashtag stream with user tags), Reddit and windowed Bluesky
  (REQ-ROLE-03) already cover retail mood.
- **Truth Social**: the policy-catalyst idea (tariffs, sector statements) is real for macro and news. But
  Berkshire decides once a day over a `holding_period_days` horizon (REQ-CTX-08). Any post that moves
  markets is covered by wire news within minutes, and the News Analyst's windowed Google News and
  WebSearch pick that coverage up. The PR's official-endpoint route is blocked by default and not PIT. A
  PIT-capable route does exist and is noted under Open questions.
- **Prompt guidance**: the PR's "do not count syndicated duplicates as independent confirmation" is a real
  gap in Berkshire. Title deduplication in `tool_news` drops exact copies, but not re-headlined wire copies,
  and no persona says so (`grep syndicat agents/` finds nothing).

## Proposed Berkshire change

None to data sources, for the reasons above. The sources are not point-in-time, cost money or are blocked
by default, and add little signal next to Yahoo, Google News, StockTwits, Reddit and Bluesky.

Optional, independent of this verdict: add one sentence to `agents/news-analyst.md` and
`agents/sentiment-analyst.md` saying to treat wire copies of one story from several outlets as one source,
not as independent confirmation. It needs no new REQ; it falls under the persona directives of REQ-ROLE-05.

## Effort and risk

- Adopting the sources: M to L (3 fetchers, a keyed-secret path, cost controls, PIT labels, new REQ rows,
  and a live/backtest parity carve-out). The risk is high relative to the value.
- The optional prompt sentence: S (under 15 minutes), with negligible risk.

## Open questions

- If a Trump-statements feed is ever wanted, the PIT-capable source is CNN's public archive
  (`https://ix.cnn.io/data/truth-social/truth_archive.json`): 36,527 posts from 2022-02-14 to now, each
  with `created_at`, keyless, about 20 MB, updated every few minutes (checked 2026-09-27). Berkshire's
  version would be a `berkshire data truths START END` engine tool. It would cache the file per run, filter
  by window and a macro keyword screen, and label engagement as current. It is unofficial and could
  disappear, and deleted posts are probably missing. It is worth building only if a backtest shows the
  News Analyst missing a tariff or policy shock that the news feeds carried late.
- Does X's recent-search endpoint reject a `start_time` a few milliseconds past the 7-day bound? This is
  expected from the API contract but not verified live (no token here).
