# PR #1416: Make Jev screening endpoint pluggable

- Upstream: TauricResearch/TradingAgents#1416 by Dangerboi, opened 2026-09-26, head `03239407f718`

## Summary

**Verdict: decline.** The PR is endpoint plumbing for a vendor call that Berkshire never makes. Berkshire's UP-017 adaptation already uses its own judge, the Sentiment Analyst (Claude), and the PR's injected-judge path has an uncaught-exception bug and wrong provenance labels.

## What it does

It builds on upstream's Jev post screening (#1376, `post_screen.py` on main). That feature sends each StockTwits and Reddit post to TypeSafe's System One endpoint with two typed questions ("about" and "stance"), drops posts scored clearly off-topic, and puts a stance count at the head of each source's block. This PR adds two ways to send those questions somewhere other than TypeSafe:

1. A `TYPESAFE_BASE_URL` environment variable replaces the hard-coded `_URL` (`post_screen.py:81` at PR head). Setting only this variable turns screening on (`post_screen.py:141-142`), and the `Authorization` header is sent only when a key is set (`post_screen.py:87-88`).
2. A module-global hook, `post_screen_judge = None` (`post_screen.py:37`). When it is set, `system_one` returns `post_screen_judge(state, questions)` and makes no HTTP request (`post_screen.py:78-79`).

Without the PR, a self-hosted System One-compatible server or a project with its own judge has to monkeypatch the module. The PR references no issue.

## Soundness

- **Bug: exceptions from an injected judge escape the screen.** The HTTP path turns every failure into `TypeSafeError`. The judge path at `post_screen.py:78-79` returns or raises whatever the callable does, and `screen()` catches only `KeyError`, `TypeError` and `TypeSafeError` (`post_screen.py:152-155`). The fetchers call `screen` without a guard (`tradingagents/dataflows/vendors/reddit.py:284`, `tradingagents/dataflows/vendors/stocktwits.py:124`). A judge that raises something else, such as a provider `RateLimitError`, `ValueError` or `requests.RequestException`, therefore crashes the Sentiment Analyst node. That breaks the promise in `sentiment_analyst.py:58-60` that no exceptions surface from the fetchers. The judge path also skips the retry and backoff loop and the answer-type check in `_answers` (`post_screen.py:117-126`).
- **Wrong provenance.** When a self-hosted endpoint or a custom judge answers, the block still says "Screened by Jev" (`post_screen.py:158`) or "Jev screening unavailable" (`post_screen.py:167`). The Sentiment Analyst and anyone reading the report cannot tell which model did the filtering. This is a data-honesty problem.
- **Thresholds are tuned to Jev.** The fixed cut-offs `_OFF_TOPIC_BELOW = 0.3` and `_STANCE_CONFIDENCE = 0.5` (`post_screen.py:40,42`) assume Jev's calibrated probabilities. A substitute judge with uncalibrated confidences will silently drop or keep a different set of posts, and nothing documents or checks this.
- **Key sent to another host.** When both `TYPESAFE_API_KEY` and `TYPESAFE_BASE_URL` are set, the TypeSafe bearer key goes to the overriding host (`post_screen.py:81,87-88`), plain `http://` included.
- **Process-global hook.** `post_screen_judge` (`post_screen.py:37`) is a module attribute rather than a key in the graph config, so every `TradingAgentsGraph` in a process shares it. Upstream elsewhere uses `DEFAULT_CONFIG` for this kind of setting.
- **Docs are stale.** The module docstring still says screening runs only with a key (`post_screen.py:1,9-11`). README.md:175-186 and the CHANGELOG are not updated.
- **Look-ahead is unaffected.** The judge sees the same window-trimmed post text as before (`sentiment_analyst.py:62-68`), so the PR has no point-in-time effect.

## Quality and maturity

- Three unit tests were added: the base URL follows the environment, a keyless self-hosted endpoint sends no `Authorization` header, and an injected judge makes no HTTP call. None of them covers a judge that raises or returns malformed answers, which is where the bug is.
- No CI checks are reported, and the PR has no reviews and no comments. It is mergeable and based on current main (v0.5.1).
- It is one day old, small and self-contained, and follows #1376 from the same area. It could plausibly merge, but its shape (an env var plus a global hook) could easily change under review, for example into a config key.

## Value to Berkshire

None that transfers.

- Berkshire adapted Jev screening as UP-017 with no vendor and no key (`docs/upstream.md:53`). The Sentiment Analyst subagent screens posts itself: it drops off-topic posts (tickers in lists, spam, a shared symbol), classifies the remaining posts into four stance classes, and opens each source with `N of M posts on-topic: …` (`agents/sentiment-analyst.md:15`). This is REQ-ROLE-03 (`docs/requirements.md:35`), checked by TST-ROLE-10 (`tests/test_plugin.py:180-185`).
- The PR's "answer the same questions with your own judge" is exactly the design Berkshire already has. The model is Claude, which the Claude-only decision requires (D1, D3), and the screening runs in the analyst's own context.
- Berkshire's version is also more honest about provenance. The count line is the analyst's own and sits next to the separate StockTwits user-tag split, whereas the PR labels any judge's output as Jev's.
- What remains is provider plumbing: an HTTP endpoint override and a Python hook for an engine component Berkshire does not have. Adopting it would mean adding a vendor or a second model, which conflicts with D1 and D3 and with the reason #1404 was declined.

## Proposed Berkshire change

None. REQ-ROLE-03 and UP-017 already cover the capability without a vendor. The only lesson to take is one Berkshire already follows: whatever does the screening has to be named in the output, and a screening failure has to degrade to unscreened posts rather than crash the analyst.

## Effort and risk

- Effort: S (nothing to build; one ledger row).
- Risk: none from declining. Adopting would bring back a vendor dependency and a second screening model beside the Claude analyst, which would duplicate or contradict its counts.
