## What it does

The whole PR builds on upstream's Jev post screening (#1376). That feature sends every StockTwits and Reddit post to TypeSafe's System One with two typed questions, "about" and "stance", drops posts that are clearly off-topic, and puts a stance count at the head of each source's block. The PR adds two ways to send those questions somewhere else:

1. A `TYPESAFE_BASE_URL` base URL, with `/v1/systemone` appended (`post_screen.py:81-82`). Setting only this variable turns screening on (`post_screen.py:142-143`), and the `Authorization` header is sent only when a key is set (`post_screen.py:88-89`).
2. A module-global hook, `post_screen_judge` (`post_screen.py:37`). When it is set, `system_one` returns `post_screen_judge(state, questions)` and makes no HTTP request (`post_screen.py:78-79`).

The practical motivation is now clear: TypeSafe has paused sign-ups, so new users reach Jev through OpenRouter.

## Soundness

I exported the new head to the scratchpad and ran `tests/test_post_screen.py`: 30 passed. I also ran a probe against the new head.

- **Still a bug: judge exceptions escape the screen.** With `post_screen_judge` set to a callable that raises `ValueError`, `jev_screen("NVDA")(["NVDA to 200"])` raised `ValueError` to the caller, confirmed by the probe. The judge path (`post_screen.py:78-79`) is not wrapped, and `screen()` catches only `KeyError`, `TypeError` and `TypeSafeError` (`post_screen.py:153-156`). The fetchers call `screen` without a guard (`tradingagents/dataflows/vendors/stocktwits.py:124`, `tradingagents/dataflows/vendors/reddit.py:284`). A judge that raises anything else therefore crashes the Sentiment Analyst node. That breaks the promise in `tradingagents/agents/analysts/sentiment_analyst.py:58-60` that no exceptions surface from the fetchers. The judge path also skips the retry loop and the answer-type check in `_answers` (`post_screen.py:117-126`).
- **Provenance: partly resolved, still wrong for the hook.** With the OpenRouter route the model really is Jev, so "Screened by Jev" (`post_screen.py:159`) is now accurate for the case the new commit targets. For a self-hosted endpoint or an injected judge, however, the probe's block still reads `Screened by Jev: 1 of the 1 posts fetched …`, and the failure text still says "Jev screening unavailable" (`post_screen.py:168`). A reader cannot tell which model did the filtering.
- **Thresholds are tuned to Jev.** `_OFF_TOPIC_BELOW = 0.3` and `_STANCE_CONFIDENCE = 0.5` (`post_screen.py:40,42`) still assume Jev's calibrated probabilities. This is harmless for OpenRouter-served Jev, but it is unchecked for any other judge.
- **The key goes to whatever host is set.** Sending the bearer key to a non-TypeSafe host is now the intended use, since the OpenRouter key goes in `TYPESAFE_API_KEY`. Nothing refuses plain `http://` for a remote host, however (`post_screen.py:82,88-89`).
- **New edge case.** A value in the earlier revision's documented form, `…/v1/systemone`, now becomes `…/v1/systemone/v1/systemone` and returns 404. The screen degrades to unscreened posts with a visible note, so no data is lost, and no released version ever used the old form.
- **Docs are still stale.** The module docstring still says screening runs only when `TYPESAFE_API_KEY` is set (`post_screen.py:1,9-11`). This has been untrue since the PR's first revision, which lets `TYPESAFE_BASE_URL` alone or a judge turn screening on. The README and CHANGELOG are not updated.
- **Process-global hook.** `post_screen_judge` is still a module attribute, not a graph-config key, so every `TradingAgentsGraph` in one process shares it.
- **Look-ahead is unaffected.** The judge sees the same window-trimmed post text as before.

## Value to Berkshire

Still none that transfers.

- Berkshire adapted Jev screening as UP-017 with no vendor and no key (`docs/upstream.md:54`). The Sentiment Analyst, a Claude subagent, screens posts itself: it drops off-topic ones, classifies stance into four classes, and opens each source with `N of M posts on-topic: …` (`agents/sentiment-analyst.md:16`, REQ-ROLE-03 at `docs/requirements.md:35`).
- The new commit makes it easier to reach a third-party model (Jev through OpenRouter). That is exactly the dependency Berkshire avoids: roles run on Claude models (D1, REQ-ROLE-02), and #1404 was declined partly for adding this vendor (`docs/upstream.md:100`). The engine (`berkshire/`) has no TypeSafe or Jev code to plug an endpoint into.
- Berkshire remains more honest about provenance, because its count line is the analyst's own. Its failure mode is also no worse, because there is no external call to fail.
