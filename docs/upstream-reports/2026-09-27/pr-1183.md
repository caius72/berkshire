# PR #1183: Add A-share market support via Eastmoney data adapter

- Author: nyxago. Opened 2026-07-29, not touched since. Head `ca322b86a13b`, one commit.
- +813 / -6 across 4 files: `tradingagents/dataflows/eastmoney.py` (new, 766 lines), `interface.py`, `symbol_utils.py`, `default_config.py`.
- Not a draft. No CI runs, no human review (the only comment is the retired Gemini bot). `mergeable: CONFLICTING`.

## Summary

**Decline.** Berkshire's users trade on eToro, and eToro lists no mainland A-shares. The adapter is also not point-in-time. Worse, it quietly swaps the default vendors to A-share-only and turns off FRED and Polymarket for everyone. The capital-flow-as-sentiment idea does not hold up either: the figure is a vendor's trade-size heuristic, not sentiment, and no free equivalent exists for anything eToro sells.

## What it does

- It adds an `eastmoney` vendor built on akshare. Despite the name, most of the data now comes from Sina: the file's own note says the Eastmoney `push2his` endpoints stopped working in July 2026.
  - OHLCV: `ak.stock_zh_a_daily`, forward-adjusted (qfq).
  - Indicators: computed locally with stockstats.
  - "Fundamentals": `ak.stock_zh_a_spot`, falling back to a 60-day OHLCV summary.
  - News: `ak.stock_news_em`.
  - The three financial-statement tools return a canned "not supported, use get_fundamentals" sentence (`eastmoney.py:583-609`).
- A `get_sentiment` function sums Eastmoney's per-day "main force / super-large / large / medium / small order net inflow" over 20 days. The PR offers it as the A-share stand-in for Reddit and StockTwits.
- It adds `is_a_share()` and `a_share_exchange()` to `symbol_utils.py:141-160`.
- It rewrites the default vendor chains to `eastmoney,alpha_vantage` and blanks out `macro_data` and `prediction_markets` (`default_config.py:134-140`).
- The problem it addresses: the default yfinance/Alpha Vantage stack is thin for bare 6-digit A-share codes, and Reddit and StockTwits do not cover them. No issue is referenced.

## Soundness

Concrete defects:

1. **The default config breaks every non-A-share user.** It contradicts the PR body's claim that it is "backward compatible and only activates for A-shares".
   - `default_config.py:134` says "yfinance 已移除 — A股优先，美股功能后期恢复" ("yfinance removed — A-shares first, US features to be restored later").
   - With this config, a US ticker fails `_validate_a_symbol` (ValueError). The router then falls through to `alpha_vantage`, which raises `VendorNotConfiguredError` without a key. So a stock install can no longer analyse AAPL.
   - `macro_data: ""` and `prediction_markets: ""` (`:139-140`) switch off FRED and Polymarket for all users.
2. **The sentiment tool is dead code.** `get_eastmoney_sentiment` is imported (`interface.py:25`) but never registered in `VENDOR_METHODS`, and no analyst tool calls it. The headline "capital flow as sentiment" feature therefore never runs. `is_a_share` and `a_share_exchange` are not called anywhere either.
3. **Look-ahead in backtests.**
   - `get_fundamentals` reads the live spot table whatever `curr_date` is (`eastmoney.py:271`).
   - Its fallback anchors on `datetime.now()`, not `curr_date` (`eastmoney.py:435`). A 2024 run is therefore shown 2026 prices labelled "Latest Price".
   - `get_sentiment` takes the newest 20 rows of the roughly 120-day fund-flow series without clamping them to `curr_date` (`eastmoney.py:722`).
   - `stock_news_em` returns only the most recent handful of articles (`eastmoney.py:638`). For a past window, the date filter therefore yields "no news", which reads as an absence rather than as data the feed cannot see.
4. **Indicator warm-up is truncated.** `get_indicator` fetches only `look_back_days` of history, then computes the indicators (`eastmoney.py:407`).
   - `close_200_sma` over a 30-day window is all NaN.
   - `macd` and `rsi` are seeded on a few weeks of data, so their values differ from those of the yfinance path.
   - The upstream yfinance path computes on a 5-year frame (`stockstats_utils.py:151,166`).
5. **Failures are returned as successes.**
   - `get_stock` returns an `"Error: …"` string instead of raising (`eastmoney.py:219`), so the router never falls back to the next vendor.
   - The agent receives Chinese error prose instead of upstream's `NoMarketDataError` sentinel.
   - `MAX_RETRIES = 1` (`eastmoney.py:50`) means `_retry` never actually retries, although its docstring says it covers transient failures.
6. **The fundamentals path is effectively always the fallback.**
   - The file's own comment says Sina spot has no PE, PB or ROE (`eastmoney.py:302-304`).
   - The match `df["代码"] == "600519"` (`eastmoney.py:289`) likely never hits, because Sina spot codes carry an `sh`/`sz`/`bj` prefix.
   - On top of that, every call downloads the whole-market spot table, several thousand rows over paginated requests.
7. **Exchange mapping is wrong at the edges.**
   - `_to_sina_symbol` sends anything that does not start with 6 or 9 to `sz` (`eastmoney.py:111`). Beijing Stock Exchange codes (4xxxxx, 8xxxxx) need the `bj` prefix, and new 920xxx BSE codes are sent to `sh`.
   - The header prints SSE only for a leading 6 (`eastmoney.py:247`), which disagrees with the routing rule.
   - `is_a_share` accepts any 6-digit string, so Korean KRX codes such as 005930 are misclassified.
8. **akshare is not added to `pyproject.toml`.** Every call hits an ImportError at runtime.

## Value to Berkshire

- **Instruments.** eToro, Berkshire's only execution venue (D2, D4), does not list mainland A-shares. `600519`, `600519.SS`, `000001.SZ` and `300750.SZ` all come back as not found.
- **What eToro does list for China exposure:**
  - H-shares: `0700.HK`, `3750.HK` (CATL), `2318.HK` (Ping An).
  - A-share ETFs: `ASHR`, `CNYA`.
  - China ETFs: `FXI`, `MCHI`, `KWEB`.
  - ADRs: `BABA`.
  - Currency: `USDCNH`.

  yfinance, Berkshire's single vendor (D3, REQ-DATA-12), already covers all of these. Berkshire even maps `.SS` and `.SZ` benchmarks already (`berkshire/config.py:24`). An A-share vendor would let Berkshire analyse stocks the user cannot trade, and the tick only covers holdings and the eToro watchlist.
- **Second vendor.** Adding one repeats the #794 decision (Twelve Data declined): more keys and dependencies, more failure modes, for no coverage gain on tradable instruments.
- **Data honesty.** On point-in-time safety and honesty about data, this adapter is well below Berkshire. It has no date clamp (REQ-DATA-01), live fundamentals on past dates (REQ-DATA-07), no `NO_DATA_AVAILABLE`/`DATA_UNAVAILABLE` markers (REQ-DATA-06), and no statements (REQ-DATA-04).
- **Capital flow as sentiment, judged on its own.** Weak, and the wrong category.
  - Every trade has a buyer and a seller. "Main-force net inflow" is Eastmoney's classification of each trade by order size and aggressor side, so it measures order flow, not sentiment. It is a proprietary, unaudited heuristic, and it is mostly coincident with the day's price move rather than leading it.
  - If it belonged anywhere, it would be a market-microstructure input for the Market Analyst. Berkshire's Sentiment Analyst counts on-topic social stance (REQ-ROLE-03), and mixing order flow into that read would muddy it.
  - For eToro instruments there is no free per-size flow feed. Hong Kong and US tape data is paid. China's Northbound Stock Connect net flow stopped daily disclosure in 2024.
  - The only transferable form is a volume-flow indicator computed from OHLCV. MFI appears in upstream's own indicator notes, and OBV is another. Berkshire could add one to REQ-DATA-03 without a vendor. Nothing in this PR shows that it would improve decisions, so it is not proposed here.

## Proposed Berkshire change

None.

- There are no tradable A-shares on eToro.
- The data layer is not point-in-time.
- The sentiment piece is dead code, and it measures the wrong thing.
- Berkshire's existing yfinance path already serves the China exposure eToro does offer: H-shares, ADRs, ETFs and CNH.

## Effort and risk

Not applicable, since there is no change. Hypothetically, adapting it would take a new vendor module with akshare, date clamping and markers, a symbol router, and new REQ-DATA rows and tests. That is effort L, with high ongoing risk: undocumented Sina and Eastmoney endpoints already broke once in July 2026, according to the PR itself.
