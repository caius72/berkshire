# PR #940: docs: note model cutoff in reproducibility

Upstream: TauricResearch/TradingAgents#940 by forge-builder, head `361b9339a78b`, opened 2026-06-01,
+6/-0 in `README.md`, refs issue #805. Reviewed 2026-09-27.

## Summary

**Verdict: adapt.** The PR's six lines are trivial, but the gap they point at is real and matters
more for Berkshire than for upstream. Berkshire runs Claude only, a third-party audit on #805 measured
recall in Claude Opus 5.5, and every Berkshire backtest surface shows hit rate and alpha with no
warning that the model may already know how those dates turned out.

## What it does

The PR adds one paragraph to the README's Reproducibility section (upstream `README.md:369-371` on
`origin/main`, where it now sits between "What does not vary anymore" and "Backtest results are not
guaranteed"). The paragraph says that pinning the analysis date limits the *retrieved data* but not
what the *model* already knows. A run on a past date is therefore a "historically grounded simulation",
and it is a causal backtest only when the model, retrieval, memory and evaluation cutoffs are aligned.
It adds no code, no check and no config.

The problem is issue #805 (open): model-level look-ahead. A model trained after the backtest window can
reason with hindsight (the NVDA AI boom, SVB, rate paths) even when every tool is point-in-time. The
maintainer fixed the data-level part separately (#1007, commit 0c1231a, undated or future news in a past
window). He kept #805 open as "a fundamental limitation a code change can't fully eliminate". Later
comments on #805 add evidence and remedies:

- lizhuojunx86, 2026-09-25: a pre-registered within-company AUC test (3,708 earnings announcements,
  2023 vs 2024 pairs). 10 of 12 models showed recall after Holm correction, **Claude Opus 5.5 at 0.766**
  and GPT-6 Astra at 0.904. DeepSeek V4 Pro and Qwen3.8 Flash showed about 0.5.
- The same author, 2026-09-26: ai-hedge-fund made its backtests "blind" by default (no ticker, industry
  or calendar dates; periods labelled t-0, t-1) in virattt/ai-hedge-fund#721. He offers an opt-in blind
  mode for TradingAgents' `run_backtest`.
- ashutosh07766: the only honest evaluation of pretraining memorisation is on data after the model's
  cutoff, or live forward testing.

## Soundness

- The text is correct and appropriately hedged. It does not claim that prompting can remove the leak,
  which is right: a line like "ignore what you know after date X" does not make a model forget.
- It is incomplete in two ways. It gives no way to *act* on the advice, such as naming the model's
  cutoff or flagging dates before it. It also uses loose wording ("evaluation stack") that the Gemini bot
  already flagged. Neither is a bug.
- It adds no look-ahead risk and has no failure behaviour to assess.
- It fixes nothing. After the PR, a TradingAgents backtest over 2023-2024 still reports alpha that a
  0.77-AUC model may partly have remembered.

## Value to Berkshire

The value is honesty about results, and it is high for backtests. The PR text itself is not needed:
Berkshire should say the same thing where its users actually read backtest numbers, not in a README
paragraph.

What Berkshire already covers (the data side of #805, as upstream does, and in places more strictly):

- Dated tools clamp to the trade date (REQ-DATA-01). Filings respect a filing lag (REQ-DATA-04).
  Point-in-time valuation and earnings exist (REQ-DATA-08/09). Profile figures are withheld on past
  dates and web and social sources are labelled as current (REQ-DATA-07, `berkshire/data.py:311-323`).
- Memory cutoff is aligned: each backtest has its own home (`berkshire/backtest.py:44-45`, REQ-BT-01),
  and lessons are filtered to those resolved by the trade date (REQ-MEM-05,
  `berkshire/pipeline.py:245`).
- Analysts get a point-in-time rule (`berkshire/pipeline.py:317-326`).

What Berkshire does not cover (the model side):

1. **No model-cutoff caveat anywhere a backtest result appears.** `berkshire/backtest.py:88-89` only
   warns about sampling and unarchived web sources ("indicative rather than repeatable"). The dashboard's
   Backtests view (`webui/src/App.jsx:207-220`) shows hit rate and mean alpha with no caveat at all.
   `skills/backtest/SKILL.md` and REQ-BT-01..04 (`docs/requirements.md:141-148`) say nothing about it.
2. **Berkshire cannot choose a model with less recall.** Upstream users could switch to a model that
   showed no measurable recall (DeepSeek V4 Pro or Qwen3.8 Flash in the #805 audit). Claude-only models
   are a Berkshire decision, and the Portfolio Manager and Research Manager run on `opus`. The one model
   named in the audit is the kind that decides the rating. So the caveat is worth more to Berkshire than
   to upstream.
3. **The run does not record which model generation ran.** State stores only the aliases
   `deep_think_llm`/`quick_think_llm` = `opus`/`sonnet` (`berkshire/pipeline.py:249-251`), and they are
   not in the run signature (`berkshire/pipeline.py:196-200`). A backtest resumed after a Claude Code
   update mixes model generations, which have different cutoffs, without saying so.
4. **Downstream roles see the ticker and date.** Only analysts get the point-in-time rule. Debaters,
   judges and the Trader still receive the instrument identity (`instrument_context`,
   `berkshire/pipeline.py:104`) and the date (`horizon_instruction`, `berkshire/pipeline.py:173-179`),
   which is the easiest route to recall. This is the route #805's blind-mode proposal closes.

Fit: no conflict. Documentation and warnings match the engine/agent split and the Claude-only
decision (D1). Berkshire re-implements the idea and copies no text, so the Apache-2.0 licence raises
nothing. The warning cannot affect order placement (backtests never create orders, REQ-BT-04).

## Proposed Berkshire change

Adapt this as a requirement plus a caveat at every backtest surface. Blind mode stays out of scope for
now (see Open questions).

1. **New requirement REQ-BT-05 (M, T).** "Every backtest summary (CLI render, `--json`, dashboard) shall
   state that the pipeline's point-in-time guards limit the data the agents see, not what the Claude
   models learned in training. Cells dated before the models' training cutoff are historically grounded
   simulations, not causal backtests. Only cells after the cutoff, or live forward runs, measure ex-ante
   skill."
2. `berkshire/backtest.py:88-89`: extend the closing caveat in `render()` with that sentence. Add the
   same sentence as a `caveat` field in `summarize()`, so the `--json` output and `/api/backtests`
   (`berkshire/server.py:142-147`) carry it without a second copy of the text.
3. `webui/src/App.jsx:212`: show `caveat` under the Backtests heading.
4. `skills/backtest/SKILL.md` step 1: when the grid starts before the orchestrating model's stated
   knowledge cutoff (Claude Code gives the session model's cutoff in its system prompt), tell the user
   which cells fall before it, and suggest a grid after the cutoff for a skill estimate. This is prose in
   the skill, with no engine code and no hard-coded cutoff table to keep up to date.
5. `docs/tradingagents-analysis.md` §3 item 2: one sentence saying that point-in-time integrity is
   data-level only (#805).
6. `docs/test-plan.md`: add TST-BT-05, which asserts that the caveat appears in `render()` and in the
   `summarize()` dict. Extend the skill inspection test to require the cutoff warning in
   `skills/backtest/SKILL.md`.

Skipped: recording the resolved model id per run (gap 3). The engine only sees the alias, and nothing
consumes the id yet. Add it when a backtest is compared across model generations.

## Effort and risk

- Effort **S** (under 2 h): two Python lines plus a dict field, one JSX line, a paragraph in the skill,
  one requirement row and one test row, one or two tests.
- Risk: very low. The change adds text and one additive JSON field, and does not touch decisions,
  gating or execution. The main risk is caveat fatigue: keep it to one sentence and do not repeat it
  per rating.

## Open questions

1. **Blind mode for backtests** (ai-hedge-fund #721, offered for TradingAgents on #805). In Berkshire it
   would mean replacing the ticker, name and dates with placeholders for debaters, judges and the Trader
   in backtest homes only. The news, sentiment and fundamentals analysts necessarily read texts that name
   the company, so blinding would be partial and could weaken grounding (REQ-CTX-01's exact-ticker
   directive). Revisit if upstream merges a blind mode, or if a Berkshire backtest shows positive alpha
   before the cutoff that disappears after it.
2. **Measuring Berkshire's own exposure.** A within-company AUC check like the #805 audit, run once on
   the `opus`/`sonnet` pair Berkshire uses, would turn the caveat into a number. It needs a paid
   earnings-label source (FMP), so it belongs outside the plugin.
3. Does the Claude Code system prompt reliably state the model's knowledge cutoff to a skill in every
   harness, including the `/loop` tick and the Agent SDK? If not, step 4 should fall back to always
   warning that pre-cutoff dates may be contaminated.
4. The #805 audit is third-party, one prompt and one window, and has not been replicated here. The
   caveat should not quote its figures as fact.
