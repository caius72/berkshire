# PR #1422: Fix LangGraph InjectedState compatibility

Head `005ef21d078d`, author hunters1011-ctrl, opened 2026-09-27, base `main`, +12/-1 in one file.

## Summary

**Verdict: decline.** The change is LangGraph import plumbing, and Berkshire has no LangGraph. Its last-resort fallback also silently turns off upstream's look-ahead clamp. Berkshire's own clamp already fails closed.

## What it does

`tradingagents/agents/tools.py:10` changes from a plain `from langgraph.prebuilt import InjectedState` to a chain of three imports. It tries `langgraph.prebuilt`, then `langgraph.prebuilt.tool_node`, and if both fail it defines a local `class InjectedState(InjectedToolArg)` that stores `field` (PR head, `tools.py:11-21`). The stated problem is LangGraph layouts that expose `InjectedState` only from `tool_node`. No issue is linked, no traceback is given, and I found no such report upstream.

Every dated tool uses `InjectedState` to get the run's `trade_date` from graph state (`tools.py:22,44,77,…`, 12 tools). That value feeds `as_of`/`as_of_window`, which is upstream's point-in-time guard (#1126/#1220 lineage).

## Soundness

I checked this by running the import chain in throwaway `uv` environments.

- **The first branch always succeeds on a consistent install.** With `langgraph==1.2.12` and `langgraph-prebuilt==1.1.0`, `langgraph.prebuilt` exports `InjectedState`, and `tool_node.InjectedState` is the same object. With `langgraph==0.4.8` and `langgraph-prebuilt==0.2.3`, branch 1 also imports. The layout the PR describes did not appear in any version I tried.
- **The failure that actually happens is dependency skew.** Upstream pins only `langgraph>=0.4.8` (`pyproject.toml:16`) and has no lockfile. With `langgraph==0.4.8`, the resolver picks `langgraph-prebuilt==1.1.0`, and importing the `langgraph.prebuilt` package itself raises `ModuleNotFoundError: langgraph.stream`. In that case:
  - branch 1 fails;
  - branch 2 fails too, because importing `langgraph.prebuilt.tool_node` runs the same broken package `__init__` first;
  - branch 3 defines the fake class;
  - then `tradingagents/graph/setup.py:4` (`from langgraph.prebuilt import ToolNode`) fails anyway.

  So the PR does not fix the case it would be triggered in. It only moves the crash from `tools.py` to `setup.py`. The real fix is a compatible `langgraph-prebuilt` bound or a lockfile.
- **Bug: the fallback silently disables the look-ahead clamp** (PR head `tools.py:16-21`). `ToolNode` injects state only for real `InjectedState` markers. I ran a probe tool annotated with an `InjectedToolArg` subclass through a `ToolNode` graph whose state carried `trade_date="2024-01-02"`. The model schema hid the argument correctly, but the tool received `trade_date=''`. The real `InjectedState` received `'2024-01-02'`. With an empty `trade_date`, `as_of` returns the model's requested date unclamped (`tradingagents/dataflows/date_window.py:79-80`, where "An empty trade_date … passes the request through"). If any environment ever reached branch 3 and still built a graph, every dated tool would serve data past the analysis date with no error. That is a fail-open on the property that most needs to fail closed.
- The fallback's `str | None` annotation is fine on Python 3.10+, which is the project floor.

## Value to Berkshire

None that transfers. Berkshire has no LangGraph or LangChain dependency.

The concept it touches is how a data tool learns the run date (REQ-DATA-01). Berkshire already handles that in a way that fails closed:
- `berkshire data --run <dir>` is required (`berkshire/cli.py:341`).
- The trade date is read from the persisted `state.json` (`berkshire/cli.py:117-119`). A missing key raises; it never becomes an empty string.
- `berkshire/data.py:76-83` `as_of` falls back to the trade date, not to the model's request, when a date does not parse.

Berkshire is already better here: upstream's `as_of` passes an empty trade date through by design, so direct calls work.

The only lesson worth noting is general: never degrade a point-in-time guard to a no-op in a compatibility path. Berkshire's design already follows it.
